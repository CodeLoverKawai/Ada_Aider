# ada-commit (Conventional Commits Standard)

<EXTREMELY-IMPORTANT>
Commit messages MUST follow the Conventional Commits specification. Never include AI auto-generator signatures (such as "Generated by AI" or "Co-authored-by: AI").
</EXTREMELY-IMPORTANT>

## Conventional Commit Structure

```text
<type>(<scope>): <summary>

[optional body explaining non-obvious rationale]

[optional footer(s)]
```

## Allowed Commit Types

| Type | When to Use |
|---|---|
| `feat` | A new feature for the user |
| `fix` | A bug fix |
| `docs` | Documentation only changes |
| `style` | Formatting, missing semi-colons, no code change |
| `refactor` | Code change that neither fixes a bug nor adds a feature |
| `perf` | Code change that improves performance |
| `test` | Adding missing tests or correcting existing tests |
| `build` | Changes that affect the build system or external dependencies |
| `ci` | Changes to CI configuration files and scripts |
| `chore` | Maintenance tasks, release bumps, dependency updates |

## Commit Formatting Guardrails

1. **Imperative Mood**: Use imperative present tense in summary ("add" not "added", "fix" not "fixed").
2. **Length Limit**: Summary line MUST be ≤ 50 characters long.
3. **No Period**: Do NOT end the summary line with a period.
4. **Breaking Changes**: Mark breaking changes with `!` after scope (`feat(api)!: drop legacy endpoint`) AND append `BREAKING CHANGE: <explanation>` in the commit footer.

## Canonical Micro-Example

```bash
git commit -m "feat(auth): implement OAuth2 token refresh"
```
